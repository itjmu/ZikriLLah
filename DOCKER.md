# ZikriLLah 0.13 — запуск через Docker Compose

Бот, API и веб запускаются в одном контейнере `muhibullo_zikrillah`. APK устанавливается на телефон отдельно. Docker-файлы лежат в корне репозитория. Нужен Docker Engine с Compose v2; проверить `docker --version` и `docker compose version`. Установку Docker на общем сервере выполняет администратор, не меняя работающие контейнеры других проектов.

## 1. Получить код

```bash
git clone https://github.com/itjmu/ZikriLLah.git
cd ZikriLLah
```

Для существующего клона вместо `clone`: проверить `git status --short`, затем `git pull --ff-only`. Если есть незакоммиченные изменения, сохранить и разобрать их прежде обновления. Не выполнять `git reset --hard`.

## 2. Подготовить секреты и данные

Полученный от владельца секретный env положить в `.env` в корне клона с правами `600`. Если файла нет, скопировать `.env.example` в `.env` и заполнить действующий `BOT_TOKEN`, `ADMIN_IDS`, `PUBLIC_URL`. Токен — только на сервере, не в Dockerfile, GitHub, вебе или APK.

```bash
chmod 600 .env
mkdir -p data
```

Compose явно задаёт `HOST=0.0.0.0`, `PORT=3107`, `DATA_DIR=/app/data`, `BOT_API_ENABLED=1`. Эти значения перекрывают одноимённые параметры `.env`:

- `0.0.0.0` нужен **внутри контейнера** для проброса порта.
- На хосте порт привязан только к `127.0.0.1:3107`.
- Данные сохраняются в `./data`, независимо от пересборки образа.
- Лимиты: 400 МБ памяти и 0.5 CPU. Это ограничения, а не гарантия достаточности при любой нагрузке; контролировать OOM и задержки.

При переносе существующей истории сначала остановить **только прежний экземпляр ZikriLLah**, сделать согласованную копию всей базы и медиа. Если раньше использовалась инструкция с systemd, данные лежат в `/var/lib/zikrillah`. В этом случае изменить в Compose только строку volume на:

```yaml
      - /var/lib/zikrillah:/app/data
```

Не запускать пустую `./data` вместо существующей базы. До запуска контейнера остановить `zikrillah.service`; после успешного перехода отключить её автозапуск. Порт 3107 и токен бота должны обслуживаться одним экземпляром. Не останавливать другие службы/контейнеры. Если системная служба раньше не создавалась, команды `systemctl` не нужны.

## 3. Запустить

```bash
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=60 zikrillah
curl --fail http://127.0.0.1:3107/api/content
```

`config --quiet` проверяет синтаксис, не печатая раскрытые секретные переменные. Не отправлять обычный `docker compose config` в публичный чат: он может вывести токен из env.

Если контейнер с именем `muhibullo_zikrillah` уже существует, выяснить, относится ли он к этой установке; чужой контейнер не удалять. При занятом порте изменить только **левый** порт в `127.0.0.1:3107:3107` и соответствующий upstream Nginx/туннеля.

Для Docker-схемы не запускать дополнительно `npm start` или `zikrillah.service`. В случае ошибки посмотреть журнал именно этого контейнера. Бот использует polling: старый экземпляр с тем же токеном должен быть выключен, webhook — удалён при осознанном переходе на polling. Проверки Telegram без вывода токена описаны в `SERVER-DEPLOYMENT.md`; внутри контейнера они выполняются через `docker compose exec -T zikrillah node --input-type=module` с тем же JavaScript, но без `--env-file`, поскольку переменные уже переданы контейнеру.

## 4. Внешний адрес

Использовать Nginx или отдельный Cloudflare-туннель, направленный на `http://127.0.0.1:3107`. Пошаговые варианты HTTPS находятся в [SERVER-DEPLOYMENT.md](SERVER-DEPLOYMENT.md), раздел 9. Не устанавливать системную службу приложения из той инструкции: здесь её заменяет контейнер. Если используется файл службы туннеля, убрать `zikrillah.service` из `After=` и создать требуемого пользователя/каталог для cloudflared либо использовать уже настроенный администратором туннель.

В `.env` поставить `PUBLIC_URL=https://ваш-адрес` без завершающего слеша. После изменения env нужен **пересозданный контейнер**, обычный `docker compose restart` не перечитывает переменные:

```bash
docker compose up -d --force-recreate zikrillah
```

Проверить `/start` и кнопку веба в Telegram. Через внешнюю сеть `/` должен вернуть 200, `/.env` и `/data/zikrillah.sqlite` — 404; POST `/api/sync` без токена — 401. Не использовать `curl -k` для обхода ошибки сертификата.

Тестовая ссылка, зашитая в APK 0.13, относится к временному туннелю на компьютере разработчика. Для переноса на сервер потребуется свой HTTPS-адрес. В APK он меняется через «Настройки → Адрес сервера», без переустановки. Сохранять базу и токен бота при переносе. Не направлять пользователей на остановленный локальный туннель.

## 5. Вход и синхронизация 0.13

- APK: «Telegram» → «Открыть Telegram» → «Старт» → вернуться в APK. Одноразовый запрос живёт 10 минут; приватный секрет запроса остаётся в APK и не передаётся в ссылке бота. Не пересылать ссылку подключения другому человеку: подключается аккаунт, нажавший «Старт».
- APK со старой привязкой использует прежний токен. При обновлении только старый адрес `trycloudflare.com` однократно заменяется тестовым адресом 0.13; собственный постоянный сервер не меняется. Адрес можно исправить в настройках.
- Подключённая кнопка «Telegram» запускает ручной обмен. Ручная синхронизация не ограничена прежним лимитом пяти попыток; параллельные запросы одного APK не запускаются.
- Автоматический обмен: 07:00, 12:00 и 22:00 по времени телефона. Пропущенные интервалы объединяются в один догоняющий обмен. Android может отложить задачу; при неудаче очередь остаётся до следующего интервала или ручного нажатия. После принудительной остановки нужно открыть APK.
- Один обмен APK отправляет до 5000 накопленных нажатий. Очень большую очередь можно отправить повторными ручными обменами либо следующими автоматическими.
- Веб из Telegram использует проверенный сервером `Telegram.WebApp.initData`; ID из URL или `initDataUnsafe` не авторизует пользователя. Проверяется HMAC и возраст входных данных до часа. Если вход истёк, открыть Mini App заново.
- Уже привязанный к другому Telegram-аккаунту веб не переключается молча: сервер отклоняет вход, чтобы не смешивать историю. Для второго аккаунта нужен отдельный профиль браузера.
- Обычный браузер сохраняет вход по `/link`. В открытом вебе автоматический обмен также привязан к трём интервалам; закрытая вкладка не выполняет таймеры. «Telegram» у подключённого пользователя запускает обмен вручную.
- Уведомления/новости приходят при обмене; это не мгновенный push. Локальное напоминание 07:00 остаётся отдельной функцией телефона.

## 6. Обновление

Сначала сделать резервную копию по следующему разделу, сохранить текущий SHA (`git rev-parse HEAD`) и ID образа (`docker inspect --format '{{.Image}}' muhibullo_zikrillah`). Не чистить старый образ до успешной проверки.

```bash
git pull --ff-only
docker compose build
docker compose up -d
docker compose logs --tail=60 zikrillah
curl --fail http://127.0.0.1:3107/api/content
```

После этого проверить `/start`, веб и APK. Изменение схемы базы при откате требует отдельной оценки; старый образ не отменяет миграции автоматически. Данные находятся в bind mount, не в образе.

## 7. Резервная копия Docker-установки

Скрипт `deploy/backup.sh` обслуживает **systemd-установку**, не Docker. Для контейнера выполнять следующий блок из корня клона от администратора. Он ненадолго останавливает только сервис `zikrillah`, сохраняет согласованную базу, медиа и env, затем возобновляет работу, если контейнер работал до копирования:

```bash
(
set -e
umask 077
mkdir -p /var/backups/zikrillah-docker
ZIKR_DATA=./data
# Если volume указывает /var/lib/zikrillah, заменить строку выше этим путём.
ZIKR_WAS_RUNNING=$(docker inspect --format '{{.State.Running}}' muhibullo_zikrillah)
trap 'if [ "$ZIKR_WAS_RUNNING" = true ]; then docker compose start zikrillah; fi' EXIT
docker compose stop zikrillah
ZIKR_BACKUP=$(mktemp -d /var/backups/zikrillah-docker/backup-XXXXXXXX)
cp .env "$ZIKR_BACKUP/zikrillah.env"
tar -C "$ZIKR_DATA" -czf "$ZIKR_BACKUP/data.tar.gz" .
tar -tzf "$ZIKR_BACKUP/data.tar.gz" >/dev/null
git rev-parse HEAD > "$ZIKR_BACKUP/commit.txt"
sha256sum "$ZIKR_BACKUP/data.tar.gz" > "$ZIKR_BACKUP/data.sha256"
printf 'Backup: %s\n' "$ZIKR_BACKUP"
)
```

Копии содержат секреты; хранить вне веба и GitHub, дублировать в защищённое внешнее хранилище. Настроить запуск этого блока по расписанию средствами администратора, контроль свободного места и политику хранения. При восстановлении остановить контейнер, сохранить текущую папку данных под другим именем, извлечь проверенный архив в пустой путь bind mount, восстановить env с правами 600 и выполнить `docker compose up -d --force-recreate`. Старую папку не удалять до проверки истории. Не извлекать старую базу поверх существующих WAL-файлов.

## 8. Проверка на телефоне

Установить APK поверх старого с той же подписью, не удаляя приложение. Проверить сохранность истории, Telegram-привязку, ручную синхронизацию, отсутствие повторов счёта, офлайн-счёт и последующий обмен. Физическую вибрацию проверять на устройстве. Тестировать рассылки только на отдельном тестовом боте, не отправлять всем пользователям ради проверки развёртывания.
