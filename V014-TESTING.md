# Версия 0.14: тестовый контур и синхронизация

## Не смешивать рабочий и тестовый сервер

Рабочая предыдущая версия уже запущена администратором. Её Docker-конфигурация, токен, база и URL этим обновлением не меняются. `Dockerfile`, `docker-compose.yml` и `.dockerignore` сохранены.

Сейчас локально проверяется версия 0.14 с тестовым токеном. Чтобы проверить объединение, APK, веб и тестовый Telegram-бот должны использовать **один локальный сервер и один Telegram-аккаунт**. Рабочий бот на другом сервере имеет другую базу и не получает тестовые записи автоматически — так и должно быть.

В настройках APK видны адрес сервера, Telegram ID после успешного обмена и время последнего обмена. Автоматическая замена прежнего адреса APK тестовым адресом удалена. Уже подключённое приложение сохраняет свой адрес; новый клиент использует тестовый адрес сборки. Для тестирования отдельной установки не удалять основное приложение с несинхронизированной историей. Не переключать рабочую установку на тестовую базу ради проверки: её локальная очередь может отправиться в тестовый контур.

После предыдущей версии 0.13 проверить адрес в APK: она могла уже заменить временный адрес. Исправление 0.14 не может угадать прежний адрес и восстановить его автоматически. Адрес можно изменить в настройках. При последующем переносе на рабочий сервер нужно сохранить его реальную базу и токен, обновить образ и использовать рабочий HTTPS-адрес. Не переносить тестовую базу поверх рабочей.

## Три способа синхронизации

1. **Подтверждённый выход.** В APK кнопка/жест «Назад» на главном экране или «Выход» в меню открывают подтверждение. При наличии сети приложение ждёт обмена перед закрытием. При ошибке можно остаться или выйти, сохранив очередь. Без сети всё остаётся локально.
2. **Раз в день при доступной сети.** Учитывается местная дата устройства. Отмечается успешное завершение автоматического обмена, а не первый неудачный запрос. Ошибка откладывает повтор минимум на 15 минут. Ручной обмен и выход не расходуют дневной автоматический обмен. Пропущенные дни не вызывают несколько обменов подряд.
3. **Вручную.** Подключённая кнопка Telegram в меню запускает обмен в любое время при наличии сети.

Расписание 07:00/12:00/22:00 и прежний лимит пяти попыток отменены. Локальное напоминание на 07:00 сохранено: оно не связано с обменом.

Накопленная очередь передаётся пакетами до 5000 событий, пока не опустеет; отдельный ручной тап для каждого пакета больше не нужен. При разрыве сети подтверждённые записи не дублируются, остальные остаются на устройстве.

**Ограничения ОС:** Android не позволяет приложению требовать подтверждение при кнопке «Домой», принудительном завершении процесса или удалении задачи системой. В этих случаях остаётся локальное сохранение и следующий доступный фоновый/ручной обмен. Android может отложить фоновую задачу. После принудительной остановки нужно снова открыть приложение.

**Веб:** используйте «Выход» в боковом меню или кнопку «Назад» Mini App: сначала подтверждение, затем ожидание обмена. Для закрытия вкладки добавлено стандартное предупреждение браузера, для Telegram — closing confirmation. Но браузер/Telegram не гарантирует уведомление приложения о подтверждённом закрытии крестиком и не обязан ждать HTTP-запрос. Поэтому закрытие крестиком не обещает синхронизации; очередь сохраняется локально. Закрытая вкладка не выполняет ежедневные таймеры. См. [ограничения beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event).

## Вход без ручного ввода кода

- APK: Telegram → открывается нужный бот → Старт → вернуться в APK.
- Обычный веб: Telegram → открывается нужный бот → Старт → вернуться в исходную вкладку.
- Mini App внутри Telegram: сервер проверяет подписанные данные Telegram и связывает с Telegram ID автоматически.
- Одноразовая ссылка живёт 10 минут. Секрет устройства не находится в ссылке и не передаётся боту. Использовать ссылку только со своего приложения, не пересылать её другому человеку.
- При попытке связать сохранённую историю с другим известным Telegram ID вход отклоняется, чтобы не объединить разных пользователей.
- Прежний `/link` и API ручного кода сохранены для совместимости старых клиентов; обычный интерфейс новой версии их не требует.

## Переключатели и содержимое

В меню один ряд: **🕶 / RU–ENG / тема / звук**. Последний переключатель последовательно включает:

1. Звук и вибрацию — исходный режим новой установки.
2. Только звук.
3. Только вибрацию.
4. Полную тишину.

Существующие предпочтения при обновлении сохраняются. Скрытый режим по-прежнему без звука и обычной вибрации; завершение круга даёт вибрацию, кроме режима полной тишины.

Каждый обмен возвращает историю, пользовательские зикры и удаления, общие зикры, темы, активную тему, фоновые изображения, звуки, текущую публикацию, актуальные уведомления и доступные пользователю рассылки. Фоны и WAV-звуки APK скачивает в кэш; при ошибке скачивания загрузка повторится при следующем обмене. В вебе загруженные картинки и WAV кэшируются service worker. Новый файл нужно хотя бы один раз получить онлайн, до этого он недоступен офлайн.

В `/admin` → управление APK/вебом добавлены:

- **«Зикр для всех»**: название, арабский текст и перевод. После подтверждения появляется у всех клиентов нового поколения и в боте. Общие зикры не являются личными удаляемыми зикрами.
- **«Добавить звук WAV»**: WAV-документ до 1 МБ, подпись — название. Рекомендуется PCM и короткая длительность до двух секунд. Максимум 20 звуков. Клиент выбирает его в настройках звука после обмена.

Новые Telegram-рассылки после подтверждения также дают получателям текст/подписи в APK и вебе. Медиа, опросы, контакты и оригинальное Telegram-оформление остаются в Telegram: в клиентах есть кнопка открытия бота. Получатели фиксируются при отправке; посторонний аккаунт не получает чужую ленту, а публичный `/api/content` её не раскрывает. Старая очередь рассылок сохранена, но тексты старых сообщений нельзя восстановить из Telegram автоматически: зеркало создаётся для новых рассылок версии 0.14. Отправка настоящей рассылки всем ради теста не нужна.

## Проверка перед обновлением рабочего сервера

1. Сделать резервную копию рабочей базы штатным способом; держать тестовую базу отдельно.
2. На тестовом аккаунте подключить APK и веб к одной тестовой ссылке и одному боту. Сравнить Telegram ID и итоговый счёт.
3. Сделать 3 офлайн-нажатия APK, вернуть Интернет, нажать Telegram. Проверить +3 в боте. В вебе нажать Telegram и проверить тот же итог.
4. Сделать 2 нажатия в боте, затем ручной обмен в APK и вебе. Итог должен увеличиться на 2, без повторного добавления прежних 3.
5. Сделать нажатие в APK, выйти с подтверждением и проверить бот. Повторить в вебе через кнопку «Выход».
6. Без сети подтвердить выход, открыть снова: счёт должен сохраниться. Вернуть сеть: автоматический обмен должен сработать, если в этот местный день ещё не было успешного автоматического обмена. Несколько переключений сети не дают несколько успешных автоматических обменов за день.
7. Настроить на тестовом боте фон, тему, WAV, общий зикр и уведомление. Синхронизировать оба клиента; проверить доступность содержимого и воспроизведение выбранного звука. Проверить все четыре режима обратной связи.
8. Проверить отмену выхода, истёкшую ссылку входа и попытку подключения другого аккаунта. Не очищать локальную историю ради исправления привязки.
9. После успешного теста отдельно обновить рабочий образ по [DOCKER.md](DOCKER.md), сохранив рабочие env, volume и HTTPS-адрес. Docker здесь не менялся. Новый APK со старым сервером сохраняет базовый обмен, но новые серверные функции появятся только после обновления сервера; общий зикр, которого на другом сервере нет, тот сервер принять не сможет.

Реальное физическое ощущение вибрации, ограничения фоновых задач конкретного телефона и закрытие Telegram проверяются на устройстве. Автоматические тесты не заменяют эти проверки.
